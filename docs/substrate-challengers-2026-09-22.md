# Durable substrates versus agent-authored factory definitions

> **Later decision, 23 September:** The [fresh engine reassessment](engine-reassessment-2026-09-23.md) recommends Temporal's stable interpreter first, Effect second, and Dagu third for development. The earlier screen below remains evidence for the other substrates.

> **Later executable results:** [Hatchet and Restate round-two trials](../tools/spikes/2026-09-22/round-two/result.md) each ran immutable v1/v2 documents through one unchanged worker/handler. Hatchet needed explicit cleanup of a bundled PostgreSQL process after owner `SIGKILL`; Restate remains conditional on its exact BUSL product/API grant. The table below is the original source screen.

22 September 2026 · Source screen following the Effect countertrial · **No product engine selected; no full feature or selection score assigned**

The shorthand “Dagu — Go — YAML — high; Hatchet — Go — code-first — very high as substrate; Restate — Rust — code-first — very high as substrate” is useful if its last column rates **durable execution potential**, not overall Exomachina fit. The engine must also fit one-command local startup, a Python Strands Director harness, product distribution rights, multiple independent harness identities, and agent-authored **versioned factory documents without routine worker rollout**. A powerful runtime does not automatically supply that publication model.

**Current ordering depends on which cost dominates.** Dagu has the clearest native agent-authoring path among these four. Hatchet, Restate and Effect are plausible durable foundations if Exomachina deliberately accepts ownership of a small factory-definition language, semantic validator, immutable catalog, interpreter and compatibility policy. That is a real subsystem, not only a file parser. Do not promote a code-first engine merely because its workflow API has high coverage.

Hatchet's embedded mode materially reopens its **no-Docker topology** screen; it does not yet prove a production bundle. Restate's express DSL-platform license grant means it is not automatically excluded for a commercial factory product, but it is not an open-source runtime and the exact product API/distribution must stay within that grant or obtain separate rights. Dagu's YAML publication advantage does not erase its GPL distribution obligations, Community control limits or transitive-version finding. No candidate here has passed the complete Strands/A2A acceptance and recovery cases.

For a self-contained product, Hatchet's default first-use sidecar download must become a pinned packaged binary; its [embedded configuration](https://docs.hatchet.run/v1/embedded) supports supplying a binary path and checksum. A harness-owned sidecar exits with that process, so several independent harnesses require a deliberate shared lifecycle owner or separate engine/store instances. For Restate, bundle the configured `restate-server` with a persistent data directory; [`restate up` is an ephemeral development command](https://github.com/restatedev/restate/blob/main/release-notes/v1.6.0.md), not the production package. Neither arrangement has a whole-install memory measurement in this evaluation.

The next discriminating comparison is one common factory fixture: publish v1 and v2 without a worker/harness rollout while v1 waits, then restart, reconcile a lost remote acknowledgement, and accept one exact artifact under two harness identities. Include the native definitions or interpreter implementation, all helper/storage processes, product rights and whole-install memory. Keep each engine's supplied guarantees separate from Exomachina's acceptance and remote-service guarantees.
