# Fresh engine reassessment brief

23 September 2026. This brief supplies the same evidence to the two independent debate agents. It does not choose a winner. The [22 September arbitration](engine-arbitration-2026-09-22.md) selected Temporal first and Dagu second for development, but its ranking is reopened because relevant Effect, Kestra, Dagu, and Zigflow evidence was missing or based on an obsolete rollout constraint.

## Accepted product boundary

- A customized Strands harness contains the Factory Module and a Director agent. Any appropriately configured instance can expose a factory A2A service. One install/start command may launch bundled local orchestration helpers; each instance has a distinct identity and durable state. The first deployment serves one organization, retaining a path to multiple customers.
- A factory definition controls graph layout, routing, waits, gates, budgets, and result acceptance. Its agent nodes are independently managed black-box A2A services selected from a directory. The factory does not deploy, restart, or inspect their internal agents. The initial directory itself is not a spike requirement; pinned test endpoints stand in for it.
- Agents may publish new versioned factory compositions from an approved vocabulary, including assignment, parallel work and typed join, conditional route, bounded repair, Director decision wait, and nested factory. They need not choose from fixed templates. Unsafe executable expressions and review or release bypasses are outside the first language profile. Existing executions retain exact definition, capability-contract, and policy bindings.
- Bundled **orchestration workers may roll out automatically** to load a new factory version. Their restart is acceptable if the user still gets one install/start command, active runs retain their exact definition plus compatible interpreter/worker build and capability/policy bindings, old versions remain available as needed, and external A2A services are untouched. There is no blanket no-worker-refresh requirement.
- One organization per deployment is the initial scope. Native local processes are acceptable; whole-harness sandboxing is deferred. An engine's complete operating cost, package and distribution rights, governance boundary, failure recovery, and product-owned code matter alongside feature coverage.
