# Temporal arbitration trial — frozen implementation and hidden A2 result

22–23 September 2026, macOS arm64. **A1, A2, A3, and the full A4 contract are partial; the exercised A5 participating/opaque receiver scenarios passed.** This is a product-shaped development comparison, not a production qualification or engine selection. The [visible run](observed.json), [hidden A2 run](hidden-observed.json), [fault run](fault-observed.json), [A2A-origin crash](a4-a2a-observed.json), [runtime Quality negatives](quality-negative-observed.json), [separate counters and A2A task IDs](counts-observed.json), [publication negatives](negative-observed.json), and [resource run](resource-observed.json) are machine-readable evidence. Their `/tmp/exo-temporal-*` state directories retain the PostgreSQL/Temporal history, immutable published packages, receiver SQLite records, and process logs. [Probe](probe.py), [fault controller](fault_probe.py), [negative checks](negative.py), and [resource controller](resource_probe.py) reproduce the cases with pinned local installations.

## A1 and A3

The interpreter accepted a v2 parent and pinned child, waited in that child's exhausted Director gate, then published v3 with the **same Python worker PID**. Each parent Workflow start recorded the full package; each child start recorded its exact child document digest. V3 ran two separate Strands/A2A 0.3.0 capability processes with distinct identities, typed source claims and counterevidence objections, and a join. A delayed counter branch completed after the source branch; the join Activity started only after both completed. Deterministic synthesis produced a valid unresolved r1, independent Quality rejected it, one repair made resolved r2, and Quality accepted that exact revision/SHA. The child recorded one authoritative acceptance in Temporal Workflow history, then the participating release receiver recorded one r2 receipt. The parent returned the child's public accepted result. A separate child received negative Quality verdicts for r1/r2/r3, made exactly two repairs, persisted a Director wait, and returned `aborted` through the parent after a current authorized command with no acceptance or release. These visible success and exhaustion runs used **distinct immutable packages and child digests**: package `00da161b...` / child `755d525a...` versus package `fa93d82d...` / child `8c3598fc...`. Their divergent outcomes do not prove one immutable v3 version can produce both. A Strands Director process also started and recovered a factory A2A Task; the fault trial used that Director for the exhausted wait and abort. [Normalized success and exhaustion evidence](oracle-observed.json) passed the common `verify_run` oracle; candidate artifact content in that file is reconstructed deterministically from the retained receiver records and corroborated by Quality digests, while Temporal history remains the execution authority.

The [publisher](definition.py) rejected review bypass, wrong join type, invalid repair bounds (0, negative, non-integer, and above two), `latest` child rebinding, unapproved service identity, executable-expression fields, and overwrite of a published digest. The revised [negative probe](negative.py) recomputes and repins the child digest for semantic mutations; diagnostics now reach the intended validator, including `release bypasses current independent Quality acceptance`, `typed join mismatch or missing predecessor`, `repair bound must be one or two`, and the extra executable-expression field rejection. Each case retains catalog SHA-256 inventory before/after, unchanged, plus freeze verification. The [Workflow Update validator](factory.py) rejected forged actor, stale revision, and wrong definition before an abort command entered history. The [remote Adapter](adapter.py) checks the pinned Quality service identity and Task binding, then the Workflow checks current revision/SHA before authoritative acceptance. There is no external Quality approval Update.

In the [post-freeze runtime probe](quality-negative-observed.json), a child was at current r2 with no authoritative acceptance. The real independent Quality service accepted a separate, digest-valid **positive r1** A2A review, and an alternate Quality identity also returned a positive r1. The Adapter's identity guard rejected the alternate service; the child remained at r2 with no acceptance immediately after both submissions, then accepted and released only its own exact r2. This is **partial** A3 runtime evidence: those extra reviews were out-of-band A2A Tasks, not injected into the active review Activity result. The frozen Workflow has no external Quality-verdict ingress. Its current-revision/identity result checks are in source, but an active forged or stale Activity result was not demonstrated.

A1's exact child/capability/identity closure is observed. The published package does **not** explicitly bind the Quality policy source revision or a service build digest; the code inventory freezes those shared files for this trial, but that is weaker than a complete per-definition policy/service-revision closure. A1 is therefore **partial** under the full contract. The branch results, Quality service, and synthesis are deterministic fixtures, not model quality.

## A4 and A5

A long-running [supervisor](supervisor.py) restarted Temporal Server and PostgreSQL after four separate forced stops: while an A2A assignment Activity remained active after remote commit; after remote Quality committed r1 but before its Activity returned; after exact r2 acceptance appeared in Workflow history while a durable timer held release; and during a nested Director wait. The controller stopped both engine ports and did not retry, flush, or resume a workflow. The original run IDs, child waits and package digests recovered through Temporal history and native Activity retries. The first three runs completed with one current r2 acceptance and one release; the fourth retained the wait. A replacement Director with the same durable identity advanced its owner epoch to 2. The stale incarnation's A2A abort returned `stale Director owner incarnation`; the replacement's abort completed the original A2A Task and parent as `aborted`.

The [additional A2A-origin crash](a4-a2a-observed.json) started the original factory through Director Task `6ec5ab05-8dd5-48a5-9d06-09ca5f33fbe0`, then stopped Temporal Server and PostgreSQL while its source assignment Activity was active. Supervisor/native retry restored the original run and the **same Task ID** to completed; each capability receiver and the release receiver recorded one effect. This crash was **before remote source commit**. The three post-commit/timer crash runs above started directly through `client.start_workflow`, not Director A2A, because the frozen Director shell sets `faults={}` and cannot expose the probe barriers. The acceptance gap demonstrates replay from a committed Workflow transition before a timer/release, but it does not simulate loss of an external continuation acknowledgement. These A4 Task-chain and acknowledgement facets remain **partial** despite observed autonomous engine recovery.

For a participating capability receiver, a new assignment committed and dropped its HTTP reply. The supervised restart and fixture-specific action lookup recovered its A2A Task with **one receiver submission attempt and one effect**. A participating release did the same by stable release ID, with one attempt, one effect, and one receipt. The separate opaque HTTP receiver committed a release and dropped its reply; its child remained in durable `unresolved-release` after another Temporal/PostgreSQL restart. Its receiver effect count stayed one, with no lookup, no receipt, and no automatic second submission. This is unresolved delivery despite a prior authoritative acceptance, not an accepted publication. A2A action lookup and release receipt lookup are fixture-specific guarantees, not general A2A or arbitrary-peer exactly-once behavior.

The [counter record](counts-observed.json) keeps receiver assignment attempts/effects, negative and positive Quality verdicts, Quality receiver actions, authoritative product acceptances, release attempts, and release effects/receipts distinct. Each accepted fault run has two assignment attempts/effects, one negative plus one positive Quality verdict, **one** product acceptance, and one participating release attempt/effect/receipt. The exhausted run has three negative verdicts and zero acceptance/release. The Quality fixture's `accepted_count=1` also appears on *rejected* reviews and is never counted as product acceptance.

## A2 freeze and withheld composition

Before the [withheld composition](../common/HIDDEN_A2_REVEAL.md) was revealed, [freeze.json](freeze.json) captured 18 interpreter, validator, publisher, Adapter, Director, worker, supervisor, server-config, lockfile, and shared-runtime files. The evaluator independently acknowledged inventory SHA-256 `aaf68094e8ecbc958e3727f1ef6f1278a913b249b3a527210475e51ee72b3099`. `freeze.py verify` returned the same digest before and after the hidden execution and all subsequent probes. Only authorable [definitions](definitions) and drivers changed after disclosure; no frozen implementation file or worker rollout changed.

The [hidden run](hidden-observed.json) published three named, simultaneous capability assignments with distinct action IDs: `source_primary` and `source_crosscheck` each returned `source_evidence@1`, while `counter_scope` returned `counter_evidence@1`. Its typed join waited for all three, preserved both source instance IDs and branch SHA-256 values, and routed on `join.route_status` before synthesis. The already-waiting v3 child kept package `32520f4e...` and child `8c3598fc...` across publication, execution, and a normal restart. The worker PID stayed `29824` during publication; a normal restart later used PID `29959` and restored the old wait.

For `requires_scope`, authored package `d2050b77...` / child `c7542e19...` rejected r1 and accepted r2 after one repair. Repeating **that exact package** in a second run also accepted r2; it did **not** exhaust. A separately authored package `5c99dc3b...` / child `a6311625...` rejected r1/r2/r3, persisted the nested child Director wait, then honored an A2A authorized abort with no acceptance/release. The `clear` binding, package `df9a736a...` / child `0d118aa5...`, accepted and released exact r1 through its Director A2A Task. These package/child digests are distinct. The frozen `synthesize.resolved` value (`true`, `false`, or `after_repair`) is fixed by the document, and deterministic Quality returns the same verdict for a given candidate. It therefore cannot produce one-repair success and two-repair exhaustion from **one immutable requires_scope version**, as the reveal requires. **A2 is partial with that exact same-version condition failed.** The separate exhaustion document shows block-path expressibility; it is not a substitute for the failed condition.

The test drivers, native JSON definitions, shared Strands/A2A services, and common fixture are separate from those candidate-owned counts. Temporal is the only durable scheduler/queue. PostgreSQL stores its engine history; receiver services own separate SQLite effect records; the Director owns a small SQLite identity/A2A alias table; the publisher owns immutable content-addressed files. The Director alias store does not schedule work. This design has a real product-owned language, validator, remote Adapter, A2A shell, and supervisor around Temporal's native durability.

The pinned run used non-development Temporal Server **1.32.0** (binary SHA-256 `f1663788fd4d8d702576b659db212b4d45a8dbfc0909eb7f7a86d0d442de6a60`), Python SDK **1.33.0**, PostgreSQL **16.15**, Strands Agents **1.57.0**, and A2A SDK **0.3.26**. The [lockfile](uv.lock) and the separate S2 lock pin the Python packages. One supervisor launched Temporal Server, PostgreSQL, one Python worker, two capability Strands processes, one Quality Strands process, one Director Strands process, and participating/opaque HTTP receivers. PostgreSQL used port 31565; Temporal frontend 35433 plus matching/history/worker, membership, metrics and pprof ports in [runtime.py](runtime.py); fixture services used 35561–35567. The supervisor owned startup, child restart and shutdown. Loopback trust PostgreSQL and `--allow-no-auth` are trial settings.

At warm ready before starting either child run, Darwin `ps` summed **1,363,984 KiB RSS** across 61 PIDs. With two children waiting, it summed **1,410,448 KiB RSS** across the same 61 PIDs; both sums double-count PostgreSQL shared pages. macOS `footprint` reported de-duplicated whole-bundle figures of **795,858,688 B at zero waits** and **826,316,856 B at two waits**. An isolated first PostgreSQL schema/bootstrap to supervisor-ready took 9.56 s; relaunch from existing state took 7.29 s and restored both waits. These are single-host snapshots/times, not peaks or a clean-machine installation. A comparable Dagu two-wait snapshot is retained in [its resource result](../dagu/resources.json); the separate 0/2/10-wait trial will examine scaling. The Temporal venv occupied about 157 MiB; the server binary about 137 MiB, SQL tool about 38 MiB, and active state about 74 MiB. Server/SDK source and package metadata indicate MIT, PostgreSQL uses the PostgreSQL License, and Strands is Apache-2.0; a shipped-binary/transitive notice audit and supported upgrade/backup/security plan remain open. No production resource envelope was supplied, so these numbers do not determine pass/fail.
