# Dagu Community arbitration result

The frozen Dagu Community v2.17.0 candidate ran the visible graph, hidden A2 composition, and injected A4 recovery paths. The result is mixed: native composition and recovery worked, while the frozen Quality guard accepted missing identity metadata in an isolated probe, and the published closure did not include service code/policy revisions. Participating lost replies and opaque uncertainty were observed; one participating-release liveness case remains unproved. The candidate is evidence for an engine decision, not a release-ready integration: the previously identified GPL-3.0-or-later distribution review still applies.

Evidence is retained in [observed.json](observed.json), [a2-observed.json](a2-observed.json), [a3-negative-evidence.json](a3-negative-evidence.json), [a3-identity-gap.json](a3-identity-gap.json), [skipped-descendant-regression.json](skipped-descendant-regression.json), [resources.json](resources.json), and [freeze.json](freeze.json). These are bounded extracts from native Dagu runs, A2A Tasks, receiver records, and product SQLite state. Raw local state and logs remain outside the repository. The shared fixture is a deterministic Strands/A2A policy harness, not a real model-quality or hosted-provider proof.

The first published native child exposed a Dagu router behavior that materially changes authoring: `router.route` skipped `accept_r1`, yet Dagu scheduled `release_r1` because it depended on that skipped target and was not itself a router target. It also scheduled `quality_r3` below a skipped `repair_r3`. The product guard denied `release_r1` (`release requires authoritative exact current acceptance`), so no unauthorized release occurred, but the child native run failed. The corrected definition explicitly names every conditional descendant in the matching router target list; the publisher now rejects missing targets. The corrected A1/A4/A5 native runs succeeded. This extra router-target wiring and validation are Dagu-specific product authoring cost, not a fixture limitation.

The participating release adapter still has a liveness gap: after recording one attempt, if the send never reached the receiver, its receipt lookup can wait indefinitely. The observed dropped-reply case committed remotely and recovered by lookup, so it does not exercise that branch. The receiver's action-ID deduplication would permit a bounded same-ID resend, but this frozen implementation does not perform it for release. The opaque receiver correctly does not resubmit in that uncertainty state. Acceptance is durable product SQLite state checked against the current candidate, exact revision/digest, pinned Quality identity and observed A2A Task; Dagu native history alone does not carry that authority.

The candidate-specific maintained Python totals 1,636 lines across the six frozen files: 330 publisher/validator, 766 product adapter and state/receipt interpreter (including A2A and delivery recovery), 77 Dagu failure reconciler, 223 Director A2A service, 43 Director client, and 197 supervisor/lifecycle. The visible v3 parent/child native YAML totals 126 lines; each hidden v4/v5 parent/child pair is 198 lines, including explicit conditional-descendant targets. The visible trial driver is 295 lines, the negative probe 132, and the post-freeze A2/identity/resource drivers 320; these 747 lines are evidence code, not runtime product code. Shared Strands/A2A services, fixture helpers, and receivers are counted once in the common package, not as Dagu engine work. Dagu schedules the authored DAG; there is no second independently maintained graph-progress queue. The product SQLite ledger stores acceptance, intents, child correlation, owner epochs, and delivery uncertainty; the nested adapter starts/correlates a separately rooted child because root-only Dagu human tasks did not supply the needed nested wait directly. This is product-owned execution logic, not native child orchestration.

The executable was the official Dagu Community `v2.17.0` Darwin arm64 binary (SHA-256 `fd855996bab956835043ae8cbb00ac3ea5211a6be6992374727b7908d393aac3`); the local S2 lock/runtime supplied CPython `3.14.3`, Strands Agents `1.57.0`, A2A SDK `0.3.26`, and PyYAML `6.0.3`. The supervisor owns local startup, restart, and shutdown of Dagu, two capability harnesses, Quality, Director, two release receivers, and the reconciler. This means nine steady processes, seven loopback HTTP ports, native Dagu file state, and product/service SQLite stores. Dagu Community's tagged guidance identifies GPL-3.0-or-later; no Go API or paid feature was used. On this macOS host, `footprint -f bytes --noCategories` across the whole supervised bundle reported **546,706,496 B** warm at ready (9 PIDs) and **708,682,032 B** with two separately rooted child Director waits and both parent adapters active (16 PIDs); fresh supervisor launch to ready took **2.48 s**. The measurement counts de-duplicated footprint across current descendants plus runtime-bound workers, not a sum of RSS; it does not include publishing time, clean-machine installation, or a distribution package. This trial used loopback unauthenticated Dagu only, and did not establish clean-machine install, portable relocation, service-manager operation, or distribution compliance. The previous [GPL bundle review](../../decision-round/dagu/gpl-bundle-review.md) remains the distribution gate.
