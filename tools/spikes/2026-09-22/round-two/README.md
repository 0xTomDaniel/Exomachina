# Six-candidate factory runtime countertrial

22 September 2026. This is a bounded engine-choice trial, not production qualification. No product runtime has been selected.

The completed six-candidate comparison and current selection judgment are in [result.md](result.md).

## Candidates and discriminating questions

| Candidate | Question this round must answer |
| --- | --- |
| Strands SDK Graph | Can a small durable run-claim/fencing and effect-reconciliation Module close the observed two-owner duplicate delivery without building another scheduler? Recheck Graph persistence using the currently documented Python session manager. |
| Dagu Community | Can a paused v1 parent remain bound to its entire child-definition closure after v2 publication, while independent factory roots recover remote work? |
| Restate | Can one pinned single-node binary plus Python handler execute new immutable factory documents through a stable handler without deployment refresh, with recoverable waits? Is the proposed product API/distribution within the inspected license grant? |
| Hatchet | Can a reproducibly bundled local engine and one unchanged Python worker execute newly published v1/v2 documents, or does the model require worker rollout? Is embedded mode usable as the proposed product topology? |
| Temporal | Can a stable interpreter on the pinned non-development server execute new documents without refreshing or retaining one worker per factory version? Do not repeat Zigflow's already observed refresh limit. |
| Effect Workflow + Cluster | Can a stable `FactoryRun` interpreter publish v2 while v1 waits, then resume the v1 binding after helper restart without registration/rollout? |

## Common synthetic factory

Use no model calls, paid services or real customer effects. The v1 fixture assigns two independent capability calls, joins their results, runs an independent review, waits for a Director decision and records one accepted delivery. V2 adds a `verify` step before review. An approved factory document may rearrange supported blocks; the trial does not require arbitrary executable expressions or unbounded cycles. Each run records its immutable definition digest and child/capability references. A direct review bypass must be rejected by the product-owned publication check when that check exists in the trial.

For each candidate, try this sequence in the smallest supported local topology: start v1 and pause at the decision; publish v2 without restarting the authoring worker or harness; start v2; kill/restart the relevant process; resume both and verify their original graph shapes. Race duplicate decisions or competing same-run owners and record whether exactly one delivery is observed. If an early packaging, license, or publication gate fails, stop there and report the boundary rather than constructing a large workaround. A candidate-specific unresolved question above may take precedence over the full sequence if it would already decide whether to continue.

Record pinned artifact versions/digests, exact processes and storage, source rights, commands, expected and observed events, imposed failures, real concurrency, resource measurements (and what they exclude), owned code, and remaining uncertainty. Do not claim exactly-once external effects from one synthetic run. External A2A submission/reconciliation and complete Strands integration are follow-up gates unless a candidate-specific trial explicitly exercises them. Reuse earlier S2/S4 harness and acceptance fixtures where practical; do not silently transfer their guarantees to a new engine.

Keep each candidate's files and temporary runtime state isolated. Compare whole-install memory only when the processes and workloads match; otherwise report measurements separately. Preserve failures as evidence. The outcome is a selection judgment across correctness, owned implementation, distribution rights, and operating cost, not a raw feature-score update.
