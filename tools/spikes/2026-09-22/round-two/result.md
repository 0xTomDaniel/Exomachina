# Six-candidate runtime decision from bounded countertrials

22 September 2026 · [protocol](README.md) · **No product engine selected**

All six requested candidates received an executable local trial. The decisive result is that **new factory versions do not inherently require a new worker deployment** on Temporal, Effect, Restate or Hatchet: one stable interpreter/handler can accept the constrained v1/v2 documents as data. Dagu used its native versioned YAML definitions; Strands Graph rebuilt versioned graphs from documents and resumed them with its documented session manager. These are narrow publication/restart findings. They do not prove a general agent-authoring language, full factory semantics, real A2A exactly-once effects, or an offline product package.

## Selection judgment

**Advance Effect and Strands Graph to one common product-shaped integration proof.** Effect has the clearest balance so far between durable local execution, MIT-licensed direct runtime packages, no PostgreSQL process and a stable document interpreter; its final transitive distribution review remains open. Strands Graph is the simplest harness-native topology and avoided a separate engine process in the fixture, but its missing ownership/recovery machinery could erase that advantage. The common proof should decide whether Graph can remain a thin Factory Module or whether Effect's local helper is cheaper overall. This is a working preference, not a runtime selection.

**Keep Dagu as the native-document alternative** because YAML publication and its small server process directly serve agent-authored factories. Its transitive child-binding policy is mandatory, and product distribution rights need a concrete GPL packaging review. **Keep Temporal as the reliability comparator:** the stable-interpreter trial makes it technically viable, but one-install PostgreSQL/server operations must earn their cost. Restate is technically attractive but stays behind a rights gate. Hatchet drops from the first implementation path: for this local product its embedded-mode scope, process tree and observed orphaned database impose more work than its no-rollout result saves.

These judgments do **not** follow directly from memory or line-count rankings. The process trees and workloads differed. For orientation only: the minimal Strands process was 71.5 MiB RSS; warm Dagu server 111.5 MiB; paused Effect helper 192.5 MiB; paused Restate server plus Python handler naively about 278 MiB; Temporal's server was 156 MiB **plus** worker and PostgreSQL; Hatchet's raw 901 MiB paused sum included 30 PostgreSQL processes and double-counted shared pages. None is a complete Strands+A2A installation or a matched physical-footprint comparison. Similarly, probe source counts exclude different amounts of reused runtime, publication and operations code.

## The proof that would settle the first build

Use one shared **approved-block** document and policy fixture, beyond each candidate's hard-coded v1/v2 shape. Publish a structurally rearranged v2 while a v1 run waits; pin each run to the full immutable definition and capability-contract closure. Run it through **two actual customized Strands harness processes**, each with its own identity and durable state, using the same local engine topology that would ship. Record reviewed artifact revisions, independent Quality findings, Director decisions, acceptance of an exact revision, and delivery as **distinct** execution-ledger events.

Then make the remote A2A receiver commit an assignment and lose its acknowledgement. Restart the helper, race two same-run owners, and require a stable effect ID plus provider-confirmed idempotency or status reconciliation. A single synthetic `deliver` marker is not artifact acceptance and does not prove external exactly-once behavior. Finally run the candidates serially from a clean offline, no-Docker bundle and measure their complete one- and two-harness process trees, startup and paused/active resources. This is the smallest common product slice likely to change the Effect-versus-Graph judgment; Dagu can enter it after its distribution/closure gates are cleared.

No new broad engine survey is indicated by this result. The unresolved work is proving one narrow factory product path, not adding more feature-matrix columns.
