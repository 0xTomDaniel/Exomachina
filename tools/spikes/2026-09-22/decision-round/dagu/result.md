# Dagu decision-round product slice

22 September 2026. **Dagu Community v2.17.0 passed the bounded product-shaped slice on macOS arm64.** Native YAML v1 and structurally different v2 ran concurrently through pinned two-level `dag.run` child closures, real Strands/A2A capability and independent Quality services, exact-current-revision acceptance, and a Strands Director A2A facade. A copied host-local bundle started with one `./run` command; after a probe hard-killed and relaunched that supervisor, it restored both waiting factory tasks, then automatically restarted the shared Dagu helper, one Director, and the capability after receiver-commit/lost-ack. Both tasks preserved their IDs and finished with the accepted artifact and one **local** release marker. This does not prove production-grade exactly-once external effects, complete ownership fencing, atomic publication, or license compliance.

## What actually ran

The [six native YAML definitions](definitions) form `factory_v1 → capability_v1 → leaf_v1` and separate v2 names/children; v2 adds a `verify` step. `human.task` gates constrain publication and final Director decision to `accepted:true`. Dagu executes the graph and persists run state. The [publisher](publisher.py) validates an approved task vocabulary, every transitive child, required review/decision dependencies, and immutable definition bytes; it records a closure SHA-256 manifest. The [adapter](adapter.py) checks the closure at remote execution, stores assignment intent and current artifact, reconciles the lost A2A acknowledgement by stable action key, verifies independent Quality's exact `r2` digest, and writes the local release marker. These are Exomachina-owned semantics, **not native Dagu guarantees**.

The [Director adapter](director_server.py) is another process of the same customized Strands harness package used by capability and Quality. It has its own durable identity, SQLite state, A2A 0.3.0 card and `message/send`/`tasks/get` endpoint. It starts/inspects native Dagu runs and submits gate decisions. A terminal A2A factory Task contains the exact accepted worker artifact, revision, SHA and distinct Quality reviewer, with run and closure binding. On restart its identity and task aliases survive while incarnation increments; old-incarnation commands fail a database check before the Dagu HTTP call. An old process that already passed this check could still issue a later HTTP call, so **in-flight owner fencing remains unproved**.

The shared [deterministic Strands/A2A fixture](../common/CONTRACT.md) supplies actual A2A calls and separately launched capability/Quality identities. The capability committed a new action and process-exited with code 23 before replying. Reconciliation used the fixture-specific `/fixture/actions/{action_id}` lookup; that route is **not standard A2A**. V1's accepted action had `attempts=1` and `accepted_count=1` after restart. Quality used a separate identity and task. Negative probes rejected stale `r1`, author self-review, duplicate acceptance, wrong run/closure binding, missing/cyclic/cross-version child, review bypass and immutable overwrite. A repeated *same* acceptance action remained one logical acceptance. No provider/model spend, real customer action, A2A 1.x compatibility, or arbitrary remote peer was tested.

The launcher built by [bundle_trial.py](bundle_trial.py) copies the unmodified pinned Dagu binary, tagged `LICENSE` and `LICENSING.md`, approved definitions and product adapters, the common harness, S2 lockfile, a uv-managed CPython 3.13.2 runtime, and its pinned venv. It generates an executable `./run`. The [supervisor](supervisor.py) runs continuously and owns a single Dagu helper plus two Directors, capability and Quality; it locks the state directory, persists ports and host-unique UUID run IDs, starts/stops children, and restarts exited children. On relaunch after its own SIGKILL, it terminates recorded orphan process groups, reuses the same state, ports and run IDs, checks unchanged published definitions, and restores all five children. The [separate probe](bundle_probe.py) killed the launcher while v1/v2 A2A Tasks were `input-required`, relaunched the same `./run`, and recovered both task aliases. It then SIGKILLed Dagu and observed automatic restart with both waits intact, killed Director A while Director B completed its own factory, released A for automatic restart, and exercised capability receiver-commit/lost-ack with automatic restart. Both factory Tasks completed with exact accepted `r2` artifacts and one local release marker. `supervisor-events.jsonl` recorded starts `[1,2,3]` for Dagu, Director A and capability. The probe uses a test-only `hold-director_a` file to keep A down while B completes. The earlier `bundle_launch.py` was a **scripted driver** that manually restarted services; its evidence is separate from this long-running supervisor.

The successful bundle run used **host-unique run IDs** because a separate [namespace trial](namespace_test.py) showed Dagu's runner socket is host-global under `/tmp/@dagu_<dag>_<hash>.sock`: two homes with the same DAG name and run ID produced one failed root; setting different `TMPDIR` values did not help. Distinct run IDs with the same DAG names succeeded concurrently. The bundle's persisted UUID IDs are a demonstrated workaround for the tested case, not a proof against every namespace collision or PID-reuse hazard. Each harness still needs a unique durable identity and state.

## Comparison-contract assessment

| Check | Observation | Product boundary / remaining gap |
| --- | --- | --- |
| Versioned publication | **Observed pass, bounded** | Native YAML v2 published while v1 waited, and each run kept its own two-level named child closure. Product publisher enforces closure digest and immutability. Root YAML is written before manifest; atomic publication, crash recovery and directory fsync are unproved. |
| Harness identity | **Observed pass** | Capability, Quality and Director A/B were separate launches of one Strands harness package with distinct persistent identities/stores; each Director exposed an A2A factory endpoint. |
| A2A assignment | **Observed pass, protocol 0.3.0** | Actual `message/send` and structured Task artifact, pinned run/action/closure. Remote harness and Director use test tokens; no 1.x or arbitrary peer proof. |
| Remote uncertainty | **Observed pass, cooperative receiver** | Receiver committed then exited before reply; adapter reconciled by stable action lookup, one attempt and one accepted fixture effect. Lookup and cooperative idempotency are product/receiver contracts. |
| Same-run contention | **Partial** | Two concurrent native human-task completions yielded one queued and one already-completed. An old Director was rejected after a newer incarnation, but only at a pre-call fence. Two independent owners running the same Dagu root and the in-flight fence race were not proven. |
| Exact acceptance | **Observed pass, deterministic Quality** | Product ledger accepted current `r2`/SHA from a distinct reviewer; negative stale/self/duplicate/wrong-binding probes passed. This is fixture judgment, not model/human quality. |
| Acceptance/engine gap | **Observed pass with explicit recovery** | Adapter exited after committed acceptance; root failed; `dagu retry --step review --downstream` resumed the same run, Quality `accepted_count=1` despite two attempts, and one local release marker. Automatic durable outbox/retry and external delivery effect were not shown. |
| Restart | **Observed pass, bounded** | SIGKILL launcher at two waits, relaunch from same state; autonomous Dagu, Director and capability child restarts preserved tasks. Native trial also restarted Dagu gracefully while waits existed. Startup orphan termination is product code. |
| Packaging and operating cost | **Observed host-local bundle** | One command starts six steady processes and six configured loopback ports, backed by Dagu files plus product SQLite stores. No Docker/JVM/remote service. Build requires `uv`, cached/downloadable Python and pinned dependencies; copied macOS-arm64 runtime worked only at its built path on the tested host. Clean-machine offline install, relocation, other OS/architecture, service-manager integration and matched peak footprint remain open. |
| Product rights | **Unresolved** | Bundle includes unmodified v2.17.0 CLI/server plus tagged license/notice files, with no Go API embedding or paid feature. GPL source/offering and distribution obligations require product-specific review. |

The `supervised3` process tree had six steady processes: supervisor, Dagu, two Directors, capability and Quality. Summed Darwin `ps` RSS was **607,088 KiB** at startup, **692,048 KiB** while both runs waited (seven processes, including a runner), **571,984 KiB** after launcher recovery, and **588,496 KiB** after both runs completed. An active polling sample reached **578,240 KiB** across eight processes. These are snapshots, not a peak or unique physical memory: shared pages are double-counted, and short-lived runners can be missed. The bundle consumed **321,408 KiB** on disk, including ~151,400 KiB for Dagu, ~115,840 KiB for the venv and ~52,868 KiB for managed Python; completed state was 888 KiB. This is a substantial per-local-bundle memory cost even without Java. Runtime `venv/bin/python` and `pyvenv.cfg` point to managed Python **inside that bundle**, not Homebrew or this source checkout, but the symlinks are absolute and post-build relocation is untested.

Product code in this bounded trial is ~166 lines of publisher, 234 lines of remote/acceptance adapter, 309 lines of Director bridge and 206 lines of supervisor, plus 94 lines of YAML. Probe/builder code is separate (~354 lines for the supervised bundle alone). These are lower bounds for a production authoring, validation, credential, recovery and lifecycle Module. Dagu's native YAML and managed run graph save graph-runtime code, but the resulting adapter/supervisor/policy footprint is material. The wrapper injects adapter environment because Dagu did not propagate arbitrary parent environment to command steps in this trial. The supervisor's process-group cleanup and saved PID handling are product-owned operating obligations; PID reuse protection, runner-subprocess cleanup during arbitrary active failure, shutdown under all crash windows and remote delivery are not fully proven.

The Dagu Darwin arm64 binary reported `2.17.0`; SHA-256 was `fd855996bab956835043ae8cbb00ac3ea5211a6be6992374727b7908d393aac3`. The [round-two trial](../../round-two/dagu/result.md) verified its release archive/checksum. The S2 [lockfile](../../s2/uv.lock) pins Strands Agents 1.57.0 and A2A SDK 0.3.26; this directory's [lockfile](uv.lock) pins PyYAML 6.0.3. The bundle inventory at `/tmp/exomachina-decision-dagu-supervised3/inventory.json` records hashes for the binary, managed Python, lockfile and tagged notices. The pinned [Dagu licensing guidance](https://github.com/dagucloud/dagu/blob/v2.17.0/LICENSING.md) states GPL-3.0-or-later and distinguishes separate CLI/server use from importing its experimental Go API. That distinction does not by itself clear a bundled commercial product; no definitive legal conclusion is drawn here.

## Reproduce

From this directory, with pinned Dagu at `/tmp/exomachina-countertrials/dagu/dagu` and its tagged `LICENSE`/`LICENSING.md` beside it:

```sh
cd ../../s2 && uv sync --frozen
cd ../decision-round/dagu && uv sync --frozen
.venv/bin/python trial.py /tmp/exomachina-decision-dagu-repro-native
.venv/bin/python negative_checks.py /tmp/exomachina-decision-dagu-repro-native
.venv/bin/python director_trial.py /tmp/exomachina-decision-dagu-repro-director
.venv/bin/python trial.py /tmp/exomachina-decision-dagu-repro-gap --acceptance-gap-fault
python3 namespace_test.py /tmp/exomachina-decision-dagu-repro-namespace
python3 bundle_trial.py /tmp/exomachina-decision-dagu-repro-bundle
```

Use fresh empty paths. The bundle builder requires `uv` during assembly, then runs its copied `./run` and separate black-box probe; the probe itself verifies hard-kill/relaunch and autonomous child recovery. The copied bundle contains trial fixture credentials and is **not** a production-ready distribution.
