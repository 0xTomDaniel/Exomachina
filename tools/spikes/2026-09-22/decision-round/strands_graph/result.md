# Strands Graph product-shaped decision probe

22 September 2026. **Bounded orchestration and A2A Director pass; production architecture still partial.** The [core probe](probe.py) used Strands Graph with the documented `FileSessionManager`, two separate shared Strands/A2A harness processes, immutable v1/v2 JSON, and an Exomachina-owned SQLite action/acceptance/decision ledger. A [follow-on Director variant](director_server.py) reused the existing S2 Strands harness/tool loop and A2A Task adapter around that Graph. Neither result selects Strands Graph or qualifies a product package.

The decisive distinction is visible in the executable: the SDK Graph supplies node/edge progression and persisted session restore; Exomachina supplies the definition publisher/validator, capability binding, actual A2A calls, remote-uncertainty recovery, exact-artifact acceptance, Director outbox, run claim and delivery fence. The **core probe's** Director was only a Graph process. The follow-on exposes a factory A2A endpoint through a subclass of the existing Strands harness; it is a bounded composition proof, not a packaged unified harness. Graph nodes are Strands `Agent`s, but this spike places their A2A calls in a fixed model fixture's `stream` method before delegating to the deterministic model. That is a spike-only Adapter placement, not proof of the intended production worker Interface.

## Evidence against the common checklist

| Check | Status and direct observation |
| --- | --- |
| Versioned publication | **Observed pass for this fixed vocabulary.** Published [v1](definitions/v1.json) and [v2](definitions/v2.json) in one process without worker refresh. Their canonical SHA-256 run bindings were `1e0efdc3…900e0` and `73a8f690…eb3fa`. V2 adds `verify`; both documents pin the `a2a:capability@r2` and `a2a:quality@r2` references. A direct `join → deliver` bypass was rejected. Fresh processes resumed v1 without `verify` and v2 with it. This is not general transitive nested-factory version closure. |
| Harness identity | **Observed pass for the bounded follow-on, partial for product packaging.** The capability and Quality endpoints were separate processes of the same [shared harness](../common/harness_server.py), with distinct durable identities/state and A2A 0.3.0. Capability restart preserved identity and advanced incarnation 1 → 2. The core probe's Director was not that harness; the [follow-on](director_server.py) used the S2 Strands harness shell as a third factory/Director A2A process. Its restart also preserved identity and advanced incarnation 1 → 2. |
| A2A assignment | **Observed pass.** Each of `research_a` and `research_b` sent real JSON-RPC A2A `message/send` to the capability harness; `review` sent another to the separate Quality harness. Task metadata and receiver lookup were checked against action ID, run ID, definition digest and role. Structured artifacts were bound to local action intents. No live model/provider ran. |
| Remote uncertainty | **Observed pass only under the fixture contract.** The capability receiver committed `run-lost:research_a`, exited before its reply, and restarted. Lookup recovered the same task with receiver attempts `1`, accepted effects `1`; the adapter did not resubmit it. A concurrently in-flight `research_b` lacked a receipt on the first trial and correctly stopped as ambiguous. The final trial retried that action after the *same receiver identity* restarted and its immediate, durable lookup reported no action; local send attempts `2`, receiver attempts/accepted effects `1/1`. A2A itself has no lookup-by-action-ID or authoritative negative-lookup rule; an eventually consistent or differently implemented peer cannot inherit this retry policy. |
| Same-run contention | **Partial.** Two fresh owner processes tried `run-race`. Owner one held a live SQLite claim at the Director delivery hook; owner two was rejected before Graph resume; owner one completed after release. The two capability receipts were each `attempts=1, accepted_count=1`, but those assignments happened during the earlier start, **before** the contested Director continuation. This did not race remote submissions or test lease expiry. The [prior synthetic race](../../round-two/strands_graph/result.md) showed two submissions after a fence was passed and an owner lease expired; receiver idempotency, not Graph, kept one synthetic acceptance. |
| Exact acceptance | **Observed pass for fixture rules; duplicate semantics qualified.** Product ledger accepted Quality's exact `r2` artifact hash and different reviewer identity, then permitted delivery only for that run/definition binding. It rejected a stale artifact revision, self-review, wrong SHA, wrong run's Quality action and a divergent repeat. An identical repeated acceptance returned the existing row idempotently; one row remained, so this is not a literal rejection of the same-result duplicate. Quality's Task and product acceptance are separate records. |
| Acceptance/engine gap | **Observed pass at a settled checkpoint.** V1 and v2 had accepted artifacts and persisted Director commands in `queued` state. The Director Graph process then received SIGKILL before either continuation. Fresh processes restored both sessions, consumed their stable command keys and marked two distinct deliveries and outbox rows `delivered`. No crash was injected after Graph delivery but before outbox completion. Delivery is a local marker, not an external exactly-once side effect. |
| Restart | **Observed pass at the named checkpoints.** The settled Director SIGKILL and receiver drop-ack/restart were real OS process events. A fresh process reconstructed the pinned graph. The follow-on additionally killed and restarted the factory A2A Director process, retrieved both original pending A2A Task IDs, and then completed them. No multi-host failover, session/ledger transaction-gap failure, or simultaneous engine storage failure was tested. |
| Packaging/operating cost | **Partial.** Core probe: one run-command Python Graph process, capability and Quality Strands/A2A processes, two loopback ports, Graph FileSessionManager state, local product SQLite, and one SQLite state per harness. The follow-on has three long-lived Strands/A2A processes and three ports. `exercise` owns startup/shutdown for the trial; no product launcher was built. With two paused Graph runs, core RSS was Graph 82,480 KiB, capability 119,952 KiB, Quality 119,648 KiB; follow-on RSS was Director 124,096 KiB, capability 118,736 KiB, Quality 118,192 KiB. RSS includes shared pages; totals are not physical footprint or matched whole-install numbers. |
| Product rights | **No apparent source-license gate in these pins; packaging still unqualified.** Installed `strands-agents==1.57.0` metadata declares Apache-2.0; the shared server's `a2a-sdk==0.3.26` metadata declares Apache-2.0. This trial ships neither a product installer nor third-party license notices and does not clear all dependency or redistribution obligations. |

The parallel `research_a`/`research_b` branches test Graph execution shape and A2A concurrency. `review` examines only the `research_a` artifact; the `research_b` result is not synthesized into the candidate. The other decision-round candidates use one capability assignment. **Their latency and RSS must not be compared as an identical workload.** Artifact revision `r2` is also distinct from factory definition revisions 1 and 2.

## Same-package Director follow-on

The [Director A2A smoke](director_smoke.py) and [record](director_observed.json) used the pinned S2 `Harness` and `FactoryPlugin` (Strands Agent/tool loop), its A2A `AgentExecutor`/`TaskStore`, and the Graph adapter in this directory. Capability and Quality remained separate instances of the shared customized Strands harness. The Director was a third Strands harness instance configured as a factory service. This reuses the harness package already proven in S2 instead of claiming the bare Graph process is an A2A service.

Both v1 and v2 `message/send` starts returned `input-required` A2A Tasks **without accepted artifacts**. After SIGKILL and restart of the Director server, its identity was stable, its incarnation changed from 1 to 2, and `tasks/get` on the original two task IDs still returned `input-required`. An observer credential could not decide. Director decisions completed both runs with distinct definition bindings, and subsequent `tasks/get` on the original task IDs projected their exact Quality-accepted artifacts. This is a meaningful same-harness proof; the fixed model still chooses the tool command mechanically, not by live agent judgment.

The follow-on introduces another 112 lines of Director Adapter plus 121 lines of smoke code. It has a remaining transaction gap: Graph start and the A2A task alias commit occur in separate SQLite stores/transactions. A crash between them could leave an unaddressable task until the caller retries with a stable run ID and the service reconciles; that path was not tested. The wrapper also does not provide full factory cards/contracts, dynamic discovery, cancellation, lease renewal, definition closure beyond the fixture, or one-install product startup. Its held sample measured Director 124,096 KiB RSS, capability 118,736 KiB and Quality 118,192 KiB; state directories were 376, 124 and 92 KiB. These are process RSS samples under a two-assignment Graph fixture.

## Source, measurements and reproduction

The complete sanitized run record is [observed.json](observed.json). The final run used `/tmp/exomachina-decision-strands-graph-6`. The intermediate `/tmp/exomachina-decision-strands-graph-3` failed safely when the second concurrent assignment was uncertain and had no recovery policy; the code then added the receiver-specific reincarnation/negative-lookup rule and later fresh-root runs passed. This failure is part of the decision evidence.

The pinned core Graph environment uses `strands-agents==1.57.0` and the earlier [lock](../../countertrials/strands_graph/uv.lock), SHA-256 `166ef59aa5dd9ac96d97151952531d58cdfe3bc1a3fb5257ba105dcf074b8149`. The shared A2A harness uses the [S2 lock](../../s2/uv.lock), SHA-256 `66fa0b284ce0e254320061a8b16d37f521e0aefc23d61c793a6cb374aa8ad877`, with `a2a-sdk==0.3.26`. The installed Python environments occupied 82,536 KiB (Graph) and 118,316 KiB (shared harness) on this Mac; these are two trial environments, not a proposed duplicated product installation. Both v1/v2 source JSON files are pinned in this directory; their raw file hashes differ from the canonical published-definition digests because canonical JSON removes whitespace.

The [core probe](probe.py) is 585 Python source lines plus 33 JSON lines. Including the Director Adapter and its smoke adds 233 Python lines, for 818 in this decision-round directory. It imports the previous pinned Graph builder/session adapter and S2 harness rather than copying their implementation. It owns the A2A client, ledger, publication-closure check, quality gate, run claim and process tests. Line count includes CLI, orchestration and assertions; it is a concrete scope indicator, **not** a production effort estimate. It still lacks discovery, lease renewal, long-running scheduler/reconciler, health supervision, cross-host storage, credential policy, complete artifact/repair semantics, and a general expression/loop DSL. The Graph session, product ledger and S2 A2A alias store are separate stores with no atomic commit across them.
