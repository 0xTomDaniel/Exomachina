# Dagu footprint while external A2A assignments are in flight

23 September 2026. This spike isolates a phase that the earlier Director-wait measurements did not exercise: an external agent has accepted an assignment and its A2A Task is still `working`. It copies the integrated Dagu v6 trial into this directory; no earlier trial, result, or verdict was edited. The local source service is a separate Strands/A2A 0.3.0 process with its own task store. The only definition change removes the source branch's unrelated lost-ack fault flag. The source fixture records a `working` Task and holds completion behind a bounded gate. All other factory and service processes use the integrated v6 topology. The published graph closure digest was `bc48a335c6d8a36fa2bd584861ec2aa18f66eae9d65fec9b2a02b2fbbd7523be`.

[`inflight_probe.py`](inflight_probe.py) admitted each parent through the actual Director A2A `message/send` route. At each sample, it queried every original Director Task, every source service Task through A2A `tasks/get`, and the native Dagu parent and child statuses. At two and ten, every Director Task was `input-required`, each parent was waiting at its native `child_gate`, each child was native `running` at `source`, and each independent source A2A Task was `working`. Each status was checked again after the footprint sample. [`observed.json`](observed.json) contains all Task IDs, parent/child run IDs, statuses, process IDs, commands, and `footprint` output metadata.

| In-flight source assignments | Full local bundle footprint | PIDs | Additional roles beyond nine base PIDs |
| ---: | ---: | ---: | --- |
| 0 | 548,312,128 B | 9 | None |
| 2 | 702,619,976 B | 15 | 2 Dagu child runners, 2 Python Dagu step adapters, 2 Dagu shell watchers |
| 10 | 1,277,924,544 B | 39 | 10 of each added role |

The nine base processes were the supervisor with the shared parent-gate scanner, Dagu server, Director, failure reconciler, two A2A capability services, A2A Quality service, and two release receivers. The same macOS `footprint -f bytes --noCategories` selection method included the supervisor tree and detached state-bound Dagu runs. This is an instantaneous, deduplicated physical footprint of a **complete local trial bundle**, not peak memory, a per-agent-harness requirement, or a general concurrency curve. The two- and ten-task admissions took 1.60 and 2.76 seconds respectively before sampling. The ten-task sample occurred while all ten source requests remained held; the fixture has a 120-second safety timeout. A separate two-task smoke also passed, and the ten-task trial ended cleanly by stopping its scoped supervisor and children.

The [earlier integrated Director-wait trial](../dagu-bridge-integration/result.md) measured 549,737,632 / 599,643,392 / 678,827,408 B with 9 PIDs at 0/2/10 **after assignments and review had finished** and both native roots were waiting for a Director decision. These phases cannot be interchanged. The processless parent gate fixed the earlier *nested wait* cost, while a live synchronous external assignment still held one Dagu child runner, one Python adapter, and one shell watcher per assignment. At ten held assignments, the footprint was about 1.28 GB, versus about 679 MB for ten completed assignments awaiting Director decisions. Those are different fresh runtimes and stages, not a matched engine comparison.

The cause is visible in the copied [`ops.py`](ops.py): `assign()` calls the synchronous A2A `send()` path and then polls in `participating_recovery()` every 0.25 seconds until the external result is available. Dagu retains the command and its runner while that step is active. The fixture used a long-running `message/send`; production A2A services may instead return a `working` Task quickly. A processless Dagu adaptation appears possible by making the assignment command short, persisting its action and remote Task IDs, then placing a native `human.task` gate after it. A shared scanner could reconcile the remote Task, validate its artifact and binding, and complete that native gate; Dagu would still schedule the downstream graph. The integrated parent bridge already demonstrates this gate/scanner arrangement for a child outcome. **This assignment adaptation has not been implemented or fault-tested**. It adds product-owned reconciliation, timeouts, cancellation policy, and a persisted-input recovery obligation; the native gate alone does not supply them.

The result does not prove Dagu uniquely pays a process per held call. The current [Effect trial](../effect-parity/helper.mjs) uses Node `execFile()` to start a Python bridge for each A2A call, and [its bridge](../effect-parity/bridge.py) synchronously sends and polls. A [matched held-call Effect follow-up](../effect-inflight-scale/result.md) observed 6/8/16 PIDs and 596,648,464 / 641,427,160 / 803,632,960 B at 0/2/10, with one retained Python bridge per working assignment. Its six-process baseline omitted the supervisor, reconciler, and opaque receiver in this Dagu bundle, so the whole-bundle totals are topology-qualified. The [Temporal trial](../../2026-09-22/arbitration/temporal/adapter.py) performs the blocking call with `asyncio.to_thread()` inside an existing worker process; no matched Temporal held-call footprint was measured here.
