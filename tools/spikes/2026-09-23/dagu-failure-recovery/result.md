# Dagu child-failure propagation and persisted-input recovery

23 September 2026. This bounded follow-up copied the [integrated v6 Dagu bridge](../dagu-bridge-integration/result.md) into a **new sibling directory** and published an immutable v7 parent/child closure. The original arbitration sources and v6 integration were not edited. All original frozen source hashes matched before and after the trials. The v7 closure digest was `c0cc57211af65b0a1f596fe9882c786374a54b45ae7f282d3006c531dc8e8a21`. The remote capability and Quality services were separate persisted Strands/A2A fixtures; only the factory graph and its bridge controlled routing.

## Observed results

| Probe | Result |
| --- | --- |
| Pre-terminal child failure | With a permanent r1 Quality adapter fault, Dagu exhausted the step's configured retries and the product reconciler made two additional bounded, same-run native retry attempts. The scanner observed exactly one failed native child step, both product retries completed, the same pinned parent/child digest, and zero acceptance/release/receipt. It sealed the child product row as `failed` with the step and digest as durable incident evidence, completed the parent `child_gate` with `child_failed`, and deliberately failed `public_result`. The **same original Director A2A Task** reported `failed`; parent and child were native `failed`. A full bundle restart preserved those IDs, statuses, and zero effects. [Evidence](failure_observed.json). |
| Attempted same-run resurrection | After restart, the fault marker was removed and `dagu retry --step quality_r1 --downstream` was invoked directly against the sealed child. The pinned Dagu command rejected it with `failed product run is sealed`; CLI exited 1, while the original A2A Task stayed `failed` and acceptance/release remained zero. This is a guard against accidental native retries after a public failure, not a complete authorization system. [Evidence](failure_observed.json). |
| Persisted gate input without enqueue, then crash | The bridge paused before completing an accepted child's parent gate. The local Dagu queue directory was made temporarily inaccessible. Dagu persisted the gate input (`child_gate=succeeded`, `doneCount=1`) but returned HTTP 503 because it could not enqueue the continuation; the parent remained native `waiting`, `public_result=not_started`, and the original Director Task `input-required`. The full bundle was then killed, queue access restored, and the same bundle restarted. The scanner called Dagu's `human-tasks/resume` endpoint. The same pinned parent/child IDs and original Task completed, with `public_result.doneCount=1`, exact accepted r2, one release receipt/effect, and no second gate completion. Dagu's server log records the queue lock permission error. [Evidence](queue_observed.json). |
| Ordinary accepted / authorized-abort regression | The copied full trial ran the accepted r2 release path, exact current-r3 Director A2A abort path, and pre-terminal failure path through the v7 bridge. The accepted path had one acceptance and one release; the abort and failure paths had zero of both. Original Director Tasks reached `completed`, `completed`, and `failed` respectively. [Evidence](observed.json). |

The original v6 bridge left a failed native child with product `state=active`, its parent waiting, and its Director Task `input-required`. In v7, `active` no longer describes the exhausted failure. The child product row is a **sealed incident**, `state=failed`, with `failure_json` recording the failed step and closure digest. The parent product row is `state=child_failed`, its bridge is `failed`, its native graph fails, and the Director Task projects `failed` without a success artifact. A future authorized repair must start a new pinned child and Director task, or define an explicit reopen protocol with a new owner epoch and fresh authority checks. This spike implements neither that reopen protocol nor automatic repair after a public failure.

## Exact change surface

- [`definitions/v7/exo_arb_parent_v7.yaml`](definitions/v7/exo_arb_parent_v7.yaml) adds an explicit `child_failed` gate input; [`publisher.py`](publisher.py) validates the two allowed gate decisions and publishes the immutable closure.
- [`bridge.py`](bridge.py) seals only a native failed child with one failed step, completed bounded retries, matching pinned closure, and no acceptance or release. It records the failure before completing the native parent gate. It also recognizes a persisted completed gate whose parent remains waiting and calls Dagu's resume endpoint, with up to three durable, spaced attempts. Bridge completion now waits for the expected native parent terminal status.
- [`ops.py`](ops.py) stores `failure_json`, rejects Dagu command execution on a sealed child, and makes the parent result step fail after rechecking the failed child. [`reconciler.py`](reconciler.py) records completion of each product retry and excludes sealed children and failed parents from further automatic retries. [`director_server.py`](director_server.py) keeps an incident Task failed even if a later native engine status changes transiently.
- [`failure_trial.py`](failure_trial.py), [`queue_trial.py`](queue_trial.py), and the copied [`trial.py`](trial.py) exercise original A2A Tasks, native parent/child IDs, restart, gate status, receipts, and effect counts. They use fresh `/tmp` state and do not alter the prior frozen trial.

## Limits that remain

The queue probe injected an **enqueue failure after input persistence**, then crashed the full bundle. It reached the same observable durable gap as a crash between input persistence and enqueue, but did not instrument a `SIGKILL` inside Dagu's few instructions in that precise interval. Dagu's [human-task documentation](https://docs.dagu.sh/writing-workflows/human-tasks) specifies the persist-then-enqueue order, identical-input idempotency, and the resume path for a stored completion whose enqueue fails. The observed HTTP 503, succeeded gate, waiting parent, restart, and resume prove recovery from that durable state for this pinned release and fixture.

The failure bridge covers **one pre-acceptance failed child step** after two completed product retries. A crash while the second `dagu retry` command is in flight leaves `completed_at` unset and the scanner refuses to seal the incident; that needs a separate stale-retry recovery rule. A failure after acceptance, or an unresolved external effect, also remains an incident for separate reconciliation rather than being reported as a harmless failed child. The scanner's three resume attempts bound this experiment; a longer queue outage needs a durable backoff/manual intervention policy. Multi-host supervisor ownership, days-long waits, production credential boundaries, Quality identity validation, participating release no-commit liveness, and GPL-compliant product distribution remain outside this trial.
