# Temporal original-Task recovery and held A2A footprint

23 September 2026. This is a bounded follow-up to the [frozen Temporal arbitration candidate](../../2026-09-22/arbitration/temporal/result.md) and its [retrospective input correction](../../2026-09-22/arbitration/temporal-input-correction/result.md). The probes live in this new sibling directory. The original frozen inventory matched its SHA-256 manifest before and after both runs. No prior candidate source, verdict, or selection document was changed. These are local fixtures, not production qualification.

## Original Director Task across two engine/store crashes

[`recovery_probe.py`](recovery_probe.py) submitted both runs through the Strands Director's actual A2A `message/send`, published one immutable `visible-v3` definition package per fresh supervisor, and recorded the original A2A Task ID plus Temporal parent/child IDs and pinned child definition digest. At the specified seam it SIGKILLed the Temporal Server process group and stopped PostgreSQL immediately, waited for the supervisor to restart both, then queried the *same* original Director Task and native workflows. Both cases passed in the final source configuration; detailed statuses, IDs, source hashes, and fixture rows are in [`recovery_observed.json`](recovery_observed.json).

| Crash seam | Before crash | After engine/store restart |
| --- | --- | --- |
| Remote Quality r1 negative verdict committed, before its Activity recorded completion | Native child `quality`; independent Quality A2A fixture held one committed negative Task/action; original Director Task `input-required` | Same Task `completed`; same parent/child IDs and pinned definition; r2 accepted; exactly one authoritative acceptance and one release effect |
| Authoritative r2 acceptance recorded, before release | Native child `accepted-before-release`, `authoritative_acceptance` present, `release_receipt` absent; original Task `input-required` | Same Task `completed`; same parent/child IDs; accepted r2 and exactly one release effect |

For **each** case, the final fixture ledgers contain one source action, one counter action, one negative and one positive Quality action, and one participating-release row with `accepted_effect_count=1`. Every recorded remote action and release row has one submission attempt. The native result contains one r2 acceptance. The Quality seam is defined by the copied adapter's marker after remote A2A receipt and before the Activity returns; the 8-second hold kept that Activity incomplete while the engine/store were killed. This observes reconciliation of a committed remote Quality action and continuation of the original parent/Director Task. The acceptance seam uses a durable 12-second Workflow timer after setting acceptance and before invoking release.

## Complete bundle with external A2A assignments in flight

[`held_assignment_probe.py`](held_assignment_probe.py) uses the same macOS `footprint -f bytes --noCategories -p <each selected PID>` process-selection function as the [earlier wait-scaling probe](../../2026-09-22/arbitration/wait-scaling/footprint_probe.py). The copied source service is an independent Strands/A2A 0.3.0 process that persists a pending source Task, reports it as `working` through actual A2A `tasks/get`, and holds `message/send` behind a bounded fixture gate. The counter service completes independently. Every factory was admitted through a distinct original Director A2A Task. At each sample and again after the sample, all original Director Tasks were `input-required`, the native parents were `awaiting-child`, the pinned native children were in `parallel`, and each source Task was still `working`. [`held_assignment_observed.json`](held_assignment_observed.json) records all Task IDs, native run IDs, digests, process IDs, roles, commands, and footprint metadata.

| Working external source Tasks | Deduplicated physical bundle footprint | PIDs | Source pending / Quality verdicts / releases |
| ---: | ---: | ---: | ---: |
| 0 | 760,597,296 B | 50 | 0 / 0 / 0 |
| 2 | 789,826,520 B | 50 | 2 / 0 / 0 |
| 10 | 836,816,048 B | 50 | 10 / 0 / 0 |

The 50 selected PIDs at all three levels were one supervisor, one PostgreSQL postmaster and 40 PostgreSQL children, one Temporal Server, one Python SDK workflow worker, the Director, two capability services, Quality, and participating/opaque release receivers. No process was added per held call in this observed range; the blocked HTTP calls remained inside the existing Python worker process. At two and ten, the counter ledger contained exactly two and ten completed actions respectively, while the source ledger contained no completed actions, every child had no authoritative acceptance or release receipt, and the Quality and release ledgers remained empty. The intentionally held scale runs were stopped after measurement; completion after releasing the source gate was not tested. This snapshot is neither peak memory nor a per-harness requirement or a concurrency law.

The [Dagu in-flight trial](../dagu-inflight-scale/result.md) measured 548,312,128 / 702,619,976 / 1,277,924,544 B and 9/15/39 PIDs at 0/2/10; the [Effect in-flight trial](../effect-inflight-scale/result.md) measured 596,648,464 / 641,427,160 / 803,632,960 B and 6/8/16 PIDs. All three use the same macOS footprint command and actual working A2A Tasks, but their complete bundles differ in store, helper, supervisor, receiver, and A2A HTTP timeout topology. Their absolute memory totals do not isolate engine overhead. The observed within-bundle Temporal increase from zero to ten was 76,218,752 B with no PID increase.

## Source delta and limits

The copied base is `temporal-input-correction`. Relocation changed only the common-fixture import paths in `adapter.py`, `director_server.py`, and `probe.py`. The new `director_server.py` admits two named *test-only* crash fault profiles through the existing Director A2A start command; the Quality profile creates an 8-second post-remote-commit Activity barrier and the acceptance profile adds a 12-second durable timer. It also contains an unused held-assignment barrier profile. The copied `adapter.py` accepts a barrier timeout field, unused by these final probes. For the in-flight trial, `probe.py` starts [`slow_harness_server.py`](slow_harness_server.py) for the source service; that file is a copy of the Dagu in-flight fixture. The copied [`long_client.py`](long_client.py) changes the shared fixture client's HTTP request timeout from 15 to 120 seconds so the synchronous `message/send` can remain in flight for the fixture's bounded hold; `adapter.py` imports it. The graph interpreter, `FactoryRun` node semantics, Temporal worker, supervisor topology, published definition format, and Quality/release receivers were otherwise unchanged. The final recovery run was repeated after this source delta and passed.

The held-call trial tests the current blocking A2A client, not a production asynchronous A2A Task subscription or reconciliation loop. The crash trials use cooperative action lookup and a participating release receiver; opaque or ambiguous external effects, full A2A v1 compatibility, longer outages, multi-host ownership, and worker-code upgrade/versioning remain separate questions. Failed native child propagation to a `failed` state on the same original Director A2A Task was **not tested** in this follow-up. The current `DirectorTaskStore.get` maps accepted/aborted/expired results and queries the parent Workflow; its behavior after an unhandled child Workflow failure needs a targeted test before claiming a durable public failure path. Neither trial removes the product-owned declarative graph interpreter or its maintenance obligation.
