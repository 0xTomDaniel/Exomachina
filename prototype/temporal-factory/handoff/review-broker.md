# Independent adversarial review: Node model broker

Reviewed `broker/exo-model.mjs`, `broker/lib/store.mjs`, and `broker/test/broker.test.mjs` at `634e80c`, against the Model broker lane, Error boundary, and Hard authoring budget in `INTERFACES.md`. The prior `handoff/pi-ai-credential-audit.md` supplied package context. All probes used synthetic credentials and fixture stores under `/tmp/exo-proto-review-634e80c/`. HTTP traffic stayed on loopback ports 46120–46125; the OAuth refresh preload returned synthetic responses locally. No real OpenAI endpoint or other tool's credential file was contacted or read. Python exception testing imported the committed `src/model_broker.py` from a temporary copy because another worker was editing its working copy.

## Findings, highest severity first

| Severity | Location | Failure scenario and reproduction |
| --- | --- | --- |
| **High** | `broker/exo-model.mjs:43-49`; `broker/lib/store.mjs:65-80,126-129` | **An override-marked store can alias another credential store.** The guard compares canonical path strings, which do not reveal hard links. I hard-linked one synthetic store's credential into a second marked store: `status` accepted the override configuration, reported signed in, and both paths had the same inode. If the other inode were the real default credential, a loopback override would receive that bearer. I did **not** link or read the actual default store. Separately, a controlled directory swap after `checkCredentialPath()` checked `secrets/` but before `readOwnerOnlyFile()` opened the credential made `readCurrent()` read a different synthetic store. Final-component `O_NOFOLLOW` and inode matching did not catch an ancestor symlink introduced in that interval. The latter requires a concurrent same-user filesystem change; the hard-link case requires permission to create the link. Both were reproduced with synthetic stores. |
| **Medium** | `broker/exo-model.mjs:283-292` | **Stale socket proof expires before unlink.** A nonresponsive live Unix listener was preserved in the ordinary probe (exit 1, socket inode unchanged). In a controlled interleaving after `socketRefused()` and before `unlinkSync()`, I moved the stale pathname and bound a new live listener there; the broker unlinked that live listener's pathname and successfully bound its own. This reproduces replacement of a live listener at the check/unlink boundary, though I did not reproduce a race between two complete broker processes. The start lock narrows the race to another same-user actor or a lock failure. |
| **Medium** | `broker/lib/store.mjs:99-107,117-120` | **Dead-PID lock recovery can remove a newly live lock.** Two recoverers can both recheck the dead owner before either unlinks. One can then replace the lock while the other unlinks its new `owner` and removes the directory. A controlled interleaving did exactly this: a live-PID lock was removed and `withPidLock()` entered its callback. Concurrent credential refreshes or starts can consequently lose serialization. A stable live-PID lock was preserved in a separate probe. |
| **Medium** | `broker/exo-model.mjs:381-394` | **Leak-scan skips every symlink, including links to noncredential copies.** I scanned the canonical credential, a copied access-token file, a symlink to that copy, and a hard link to the credential. The copy and hard link produced hits; the symlink produced neither a hit nor an exclusion. Thus a token-bearing file reached through a symlink is invisible even when the symlink is an explicit scan argument. This violates the one-canonical-file exclusion rule. Reproduced. |
| **Low / contract tension** | `broker/exo-model.mjs:103-108,225,236,297-298` | **Exact-token redaction changes stream content.** An arbitrary JWT-shaped synthetic model text was preserved byte-for-byte in its delta and `done` content. When model text exactly matched the synthetic credential access value, both delta and `done` contained `[redacted]`. Reproduced. This protects the credential as the interface requires, but the stream is not lossless for that content; any strict claim that redaction *never* alters deltas or `done` needs this exception stated. |

## Checks that held

- **Error boundary:** Planted non-JWT diagnostic text and an off-allowlist `error.code` in JSON 400/500 bodies and SSE `error`/`response.failed` events. The socket returned only fixed messages and bounded status/code (`other` for the off-allowlist HTTP code); the text appeared in neither `broker-events.jsonl` nor captured broker stdout/stderr. A Python `PiBrokerModel.stream()` exception from the committed adapter contained only `model broker provider: Codex provider request failed`. The SSE errors carried status 200 and omitted `code`, without exposing the diagnostic. This covers the tested provider shapes, not every possible pi-ai event.
- **File modes and normal atomic writes:** Symlinked credential, `secrets/`, and `run/` paths were refused by the CLI. A direct store read refused a group-readable credential; CLI startup tightened owner-held wide modes to `0700` directories and a `0600` credential. A controlled final-file swap between stat and open was rejected by the inode check. Eight concurrent synthetic `refresh` operations all succeeded through the broker, yielded eight local mock OAuth records, left a valid `0600` credential, and produced zero parse failures during repeated reads. The separate store-level concurrency probe also produced zero partial reads.
- **Override paths:** Explicit default home, a relative path to it, and a `..` spelling of it all failed configuration before a request. The hard-link and ancestor-swap findings above remain reachable in a marked, nondefault home. No real default credential was opened.
- **Egress:** A string URL and a `Request` with `redirect: follow` both returned the loopback server's 302 without following its external `Location`. A disallowed-host `Request` and a loopback-looking URL whose parsed host was external were refused. A loopback URL with userinfo was rejected by Node fetch before a request. Only two requests reached the loopback server; neither redirect target was contacted.
- **Socket/lock stable cases:** A silent live socket with a dead PID in its ready file was not removed; its inode stayed unchanged. A stable live-PID lock timed out and retained its owner. The race findings above require a change between validation and removal.

The committed tests cover ordinary symlink rejection, bounded HTTP errors, race-to-start, stale artifacts, JWT-shaped tool arguments, and sequential refresh. They do not cover hard-link aliasing, ancestor swaps, symlinked leak-scan copies, or the controlled stale-artifact interleavings above. Review probes live at `/tmp/exo-proto-review-634e80c/`; no product source or test file was edited for this review.
