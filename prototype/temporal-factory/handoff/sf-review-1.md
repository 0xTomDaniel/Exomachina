# Independent review 1 — integrated lanes A + R

24 September 2026. Read-only review of commit `3b4d4ea` against `briefs/single-factory.md`. No source or test files were edited; no live broker was used. The scenario and interpreter/director lanes were not present in this tree, so this review does not claim an integrated route result.

## Findings, ranked by severity

1. **High — R1-d can pass without an answer.** `services/agent_roles.py:360` (`usefulness_check`) verifies claim count, citation ID membership, nonempty markdown and four headings, but does not verify that the live/fixture status, remaining gaps or next priority are actually answered. A report with three unrelated claims citing `E1` and `TBD` under every required heading returns `{"ok": true, "reasons": []}` in a read-only probe. If the scenario uses this return as the R1-d usefulness verdict, it can report a false pass. **Fix:** make the evidence record include an independent content judgment for those three required parts (human review or a separate, explicitly labeled model assessment); keep this function as a structural check and do not let its `ok` alone satisfy R1-d.

2. **Medium — research and Quality model calls lack the promised read-only observation route.** `services/model_agent.py:523` places `GET /_test/observe` inside `if test_controls`, while `services/testbed.py:172` passes `--test-controls` only to the synthesizer. Thus an A2A-only scenario can inspect the synthesizer's calls, but cannot obtain the research or Quality `model_calls` rows needed for SF-2, G-2 and G-3 through the same interface. Reading each SQLite store directly is possible for this local fixture, but must be implemented and evidenced explicitly; `tasks/get` does not expose sessions, call counts, model IDs or `live`. **Fix:** expose authenticated, read-only `/_test/observe` on all four report agents while retaining stimulus mutation endpoints on the synthesizer only, or have the scenario read and preserve all four SQLite audits.

3. **Medium — stimulus audit and Task completion are not atomic across restart.** `services/model_agent.py:248` commits `stimulus_log` before `services/model_agent.py:414` commits the finished artifact. If the synthesizer exits after the first commit, the working Task recovers and calls `apply_stimulus` again, producing two log rows for one `(task_id, revision)`. R2-a requires exactly one planted claim and can fail spuriously even if the final artifact has only one. **Fix:** commit stimulus application metadata and the completed artifact in one transaction, or make the log unique and idempotent on `(stimulus_id, task_id, revision)` and verify its stored hash matches the final artifact.

4. **Medium — scripted Quality reads the test stimulus catalog.** `services/agent_roles.py:348` loads `scenarios/sf_stimuli.json` in the Quality scripted reply and rejects claims by exact text match. This gives the Quality process knowledge of the synthesizer's test control even though `services/testbed.py:172` correctly enables the control endpoint only on the synthesizer. The synthetic route can therefore get the expected rejection from a catalog match without a packet-based Quality decision; it is useful as wiring evidence, but a false proxy for independent review. **Fix:** keep stimulus data on the synthesizer/scenario side and make scripted Quality evaluate the packet and candidate through a generic deterministic rubric, or label this exact-match behavior explicitly as scripted route control and exclude it from any independence claim.

5. **Low — a literal services import audit will fail.** `services/testbed.py:17` adds `src/` to the import path and `services/testbed.py:18` imports `agent_binding`, whereas SF-2 says no service imports a factory module other than `model_broker`. `testbed.py` is a fixture launcher rather than an agent process, but a static audit over `services/*.py` will still report it (and legacy service modules also have preexisting `src/` imports). **Fix:** move pin generation into scenario/orchestrator code or a neutral shared package, then define the audit over the frozen architecture's active report services without silently waiving import findings.

## No issue found in the reviewed paths

- **Task identity and recovery:** `Ledger.accept` uses a unique `action_id`, compares a payload fingerprint and commits the working row before `on_message_send` returns. Startup reschedules working rows; completed rows retain their Task IDs and artifacts.
- **Sessions and budget:** each Task derives a session from its durable agent identity and Task ID; every `RecordedModel.stream` attempt, including validation retries, increments the same Task's durable count before the call. The broker client sends that session and the Node stream event records it. The 240-second deadline is carried forward from Task creation after restart. No live provider was exercised here.
- **Quality authority:** candidate/reviewer fields in the emitted verdict are bound from the request and local identity, `decided_by` distinguishes precheck from model parsing, and `accepted` is checked against blocking findings. The strict JSON parser matches the prompts' requested shapes and permits a single fenced JSON block; live `gpt-6-sol` formatting remains unobserved.
- **Pins and credentials:** durable identity plus stable card/contract construction support pins across same-port restarts; the live provider rejects `EXO_MODEL_HOME` and `EXO_CODEX_BASE_URL`. The reviewed Python files do not open broker credentials or invoke login, refresh or logout.
