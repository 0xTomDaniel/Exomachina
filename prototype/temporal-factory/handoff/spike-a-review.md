# Spike A2 factory-side read-only review

Reviewed the current uncommitted factory diff and new files against `briefs/spike-a.md` and the fixed wire contract. The latest recorded real-process attempt, `evidence/spike-a/delayed.json` (`/tmp/exo-qual-a-delayed-20260923-a2d`), reports A-1 through A-5 passing. Its logs show polling the original Task on the moved port, an impostor pin incident, a no-Task-ID lost-response recovery that returned the original Task ID, and an artifact incident with no release. The findings below concern paths and assertions that this successful attempt does not settle. No scenario or tests were run for this review.

## High

1. **A timed-out Activity can leave a live polling thread that overwrites a newer journal decision.** `src/adapter.py:133-136`, `src/long_client.py:67`, `src/factory.py:20-26`, `src/a2a_outcome.py:177-181`. `assign` calls the synchronous poller through `asyncio.to_thread`, but the HTTP operation can wait 120 seconds while Temporal times out the Activity after 90. The attempted heartbeat runs in that thread and raises `RuntimeError`; the worker log for the latest attempt records `coroutine '_ActivityWorker._heartbeat_async' was never awaited`. Temporal can start another attempt while the old thread still holds an earlier `OutcomeRecord`. Both attempts use unconditional `journal.put`, so a slow old `tasks/get` can overwrite a newer `incident` or `confirmed` row after a snapshot change or mismatched artifact. A peer that slowly streams a response can keep the old thread alive beyond the nominal socket inactivity timeout. This compromises durable recovery and incident state even though the conforming delayed agent's idempotency prevents a second effect. **Affected checks:** A-3b, A-4, A-5; the timeout/heartbeat invariant.

2. **Publication can declare idempotent resend without verifying that the served contract declares it.** `src/agent_binding.py:41-61`, `services/testbed.py:193-198`. `pin` verifies that the extension digest matches the bytes served at `/contract` and that the extension uses the expected contract name, then unconditionally writes `reconcile: "a2a-idempotent-resend"`. It never checks the document's `reconcile`, action-key, same-payload replay, or commit-before-response clauses. For example, a replacement agent can serve a self-consistent card and digest for a document declaring `reconcile: "opaque"`; publication still grants resend. If its first response is lost, `src/adapter.py:70-85` sends again and a non-idempotent agent can produce a second effect. The stub contract in `tests/test_agent_binding.py:18` lacks the wire contract's idempotency clauses yet is accepted by `pin`. **Affected checks:** A-2, A-4; the per-action effect-count invariant.

## Medium

3. **An incomplete async pin silently selects the legacy binding-URL send path.** `src/adapter.py:279-284`. The dispatch decision tests only whether `card_sha256` exists, rather than selecting the pinned `reconcile` mode and requiring every async pin field. A published contract with `reconcile: "a2a-idempotent-resend"` but an omitted card digest takes `_invoke`, which sends to the package binding URL after only a fixture `/health` check. The current delayed fixture rejects that legacy request shape, but a receiver accepting it would see an unverified send, and no identity snapshot is consulted. An incomplete async contract should become an incident before any send. **Affected check:** A-2.

4. **A-4's pass verdict does not require a lost-response, no-ID state at restart.** `scenarios/spike_a_delayed.py:290-307`, `scenarios/spike_a_delayed.py:173-195`. The scenario saves `first = journal(...)` but `verdict` never checks its phase or absent `task_id`, nor that a post-restart `agent-task-journaled` event has `resend: true`. If the drop fault misses the action or the first reply is journaled before shutdown, ordinary Task-ID polling after restart can satisfy every A-4 condition and be reported as lost-response recovery. The latest recorded attempt **does** show `first.phase: unknown`, `first.task_id: null`, and a resend of the original Task ID; the gap is in the reusable verdict. **Affected check:** A-4.

5. **The move and impostor verdicts can pass without their decisive transition.** `scenarios/spike_a_delayed.py:254-279`, `scenarios/spike_a_delayed.py:173-195`. A-3a does not assert that `first.phase` is `working` when the old agent stops or that `tasks/get` later used the new snapshot URL; a Task already confirmed before the move could pass the same-ID and acceptance conditions without testing URL migration. A-3b checks failure and zero impostor effects but not that the journal reason is `pinned-agent-verification-failed`; an unrelated adapter failure after the snapshot swap could pass. The latest attempt's logs contain the required old/new-port polls and pin incident, so these are false-positive risks in future runs rather than failures of that attempt. **Affected checks:** A-3a, A-3b.
