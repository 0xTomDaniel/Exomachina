# Independent review 2 — integrated single factory

24 September 2026. Read-only review of `sf/roles` at `6b89117` against the frozen brief and Amendment A1. No source or test file was changed. No scenario, live broker, or listener was started. The only write is this handoff. The findings below concern the integrated product path and the honesty of `scenarios/single_factory.py`; they do not repeat the five resolved Review 1 items.

## Findings, ranked by severity

1. **High — the route checkers can certify acceptance without the accepting Quality verdict naming the released SHA.** `scenarios/single_factory.py:237-243,276-278,291-300,314-324` checks the R1 verdict's SHA but not its candidate revision/author or remote Task and journal binding; R2-d checks `ak2 == "r2"` and exact release against the synthesizer's `h2`, but never compares `av2.candidate.sha256` with `h2`; R2-b and R3-b similarly omit exact candidate SHA, reviewer identity, completed Task, and journal binding. A pure-function probe with an accepting R2 verdict naming SHA `unrelated`, a synthesizer artifact naming `real-r2`, and a release/Task naming `real-r2` returned `R2-d: pass`. `R1-e` at `:259-261` also passes for one Quality row with no verdict at all. **Fix:** create one checker helper that requires the completed Quality Task, its artifact ID/content SHA, action/run/definition/reviewer pin, matching confirmed journal Task ID, `candidate == {revision, sha256, author}` of the corresponding synthesis Task, and `decided_by:model` plus a live model call for live checks. Require it in R1-c/e, R2-b/d, and each R3-b revision; bind release and Task to that same candidate. The product path itself has stronger checks and is cleared below.

2. **High — route and outcome completeness are not established by SF-3 or G-1.** `scenarios/single_factory.py:189-202,350-356,387-393` tests six workflow summaries in total and one common version tuple, but does not require one parent and one child for *each* of routes 1, 2 and 3, nor match their IDs to each original Task. A probe with all six summaries in route 1 returned `SF-3: pass`. G-1 requires six IDs and a nonempty confirmed subset of journal rows; one confirmed child row for six IDs returned `G-1: pass`. Thus missing research, Quality, or release journal outcomes need not fail G-1. For a live run, G-7 accepts a copied `structural-pass` synthetic summary without checking its home, source revision, manifest/build, or route inventory. **Fix:** require route keys exactly `1,2,3`, unique Task/parent/child IDs, two exported histories per route with those IDs and the pinned build, and the expected action IDs and confirmed outcome kinds per revision. Persist and compare the synthetic evidence file digest and code/build identity before using it as the live prerequisite. `:605-613` must inspect the actual pinned behavior enum, rather than turning any truthy behavior into the string `PINNED`.

3. **High — raw Temporal evidence exports the Director credential and package closure into the repo evidence tree.** `src/harness.py:231-240` starts the workflow with `director.token`, actor and full package/closure (including bindings); `src/factory.py:295-305` copies that input to the child; `scenarios/live_authoring.py:261-289` writes each full history JSON under `evidence/single-factory/` when called by `scenarios/single_factory.py:796-810`. The token is not a broker credential, so G-4's broker leak scan does not prove it absent. A preserved or committed history is enough to disclose the Director update credential while that run is open. `FactoryRun.status` at `src/factory.py:60-80` also returns `owner_epoch` and `authorized_actor`, and the caller Task metadata at `src/harness.py:514-524` exposes the authorized actor. **Fix:** keep the full history in the restricted trial home if needed for replay, export a redacted evidence copy with credential-bearing input payloads replaced by hashes, and record both file digests and redaction coverage. Remove actor/epoch from the general status projection or use a separate privileged internal query; remove `authorized_input_actor` from A2A Task metadata. The model-facing `inspect_bound_run` projection is already limited.

4. **Medium — factory mode still accepts structured caller commands, bypassing the live Director turn.** `src/harness_server.py:248-260` routes a caller DataPart to `Director.invoke(command, ...)`; `src/harness.py:397-413` then uses `ToolCallingModelFixture`, and `:272-349` can start or abort through `perform`. A bearer fixture caller with the current revision/SHA can send `{op:"abort", ...}` directly to the original Task, without the registered follow-up text, live `inspect_run`, or a model-decided `decide_wait`. The graph, Quality and revision checks still constrain the action, but this violates the frozen text-only caller/Director route. **Fix:** reject DataParts on factory-mode A2A requests and retain structured fixture commands only behind an explicitly separate legacy test path.

5. **Medium — R1-d's structural evidence does not bind the delivered markdown to the reviewed report.** `scenarios/single_factory.py:118-130,244-258,843-858` requires a nonempty Task TextPart and a truthy report path, while `usefulness_check` and citation checks inspect the synthesizer content. It never compares the Task TextPart or saved file bytes to that content's `markdown`, nor confirms the release row's content bytes. A hand-built record with valid synthesis claims and an unrelated Task TextPart passes the structural pieces when the SHA fields are copied. **Fix:** compare the saved file and Task TextPart byte for byte to the exact synthesis report named by acceptance and release, and validate the release content digest. Amendment A1's separate orchestrator semantic reading is correctly left pending; do not turn this structural pass into a semantic pass.

6. **Medium — stimulus checks do not prove factory invisibility or route-3 exclusivity.** `scenarios/single_factory.py:263-272,302-313,831-842` sets `stimulus_absent_from_factory` by looking for the literal JSON substring `"stimulus"` in caller messages, run inputs and agent briefs. A factory brief or workflow input carrying `append_claim` without that key passes. R3-a filters the global stimulus log to route 3, so an additional application on route 1 or 2 can coexist with `R3-a: pass`. **Fix:** inspect the relevant Temporal start/activity inputs and Director tool arguments as structured objects against an explicit forbidden control-key set, and compare the entire stimulus log with the exact expected `(run_id, revision, task_id, sha256_after)` set for routes 2 and 3, with no row for route 1.

7. **Medium — the route-3 Director inspection may belong to an earlier turn.** `scenarios/single_factory.py:328-348` only requires an accepted `inspect_run` row before an accepted `decide_wait` row. A probe with the inspection on message `old-turn` and the abort on message `follow-up` returned `R3-d: pass`. R3-e accepts any nonempty collection of budget-compliant turns, even with no route-3 follow-up turn. **Fix:** bind both accepted calls to the follow-up message ID, original Task/context, and one recorded live turn; require no other accepted decision for that wait. Require the expected turn count per route before applying the 4/4/90 budget test.

8. **Medium — G-2, G-3 and SF-2 can pass with incomplete call/pin inventory.** `scenarios/single_factory.py:173-188,357-376,521-597` requires distinct stores and nonempty per-task pin flags, but the collector counts pin verification events by total rather than pairing one with each send/poll in order. G-2 tests the recorded calls it happens to find and samples one broker PID after authoring and one per route; it does not prove no broker restart between samples or compare Director/authoring call records to stream events. G-3 tests only Tasks found in SQLite, so an omitted Task/store row is not itself detected there. **Fix:** derive the expected per-route action/Task inventory from journal and history, require a completed or failed Task row and bounded call records for each, pair every dispatch/poll event with its preceding pin resolution, and reconcile broker PID/session events with each model call and Director/authoring count.

9. **Medium — G-4 coverage is asserted through constants.** `scenarios/single_factory.py:377-381,859-868` sets all four `covered_*` fields to `True` regardless of `candidate_files()` count or the scanner's input paths; the checker accepts those flags and `positive_control.detected` without inspecting the saved scan's coverage. A record with zero real hits, four true flags, and a separate detected control returns `G-4: pass` even if no candidate file was scanned. **Fix:** retain the exact canonical scan input paths and candidate manifest/digests, require a nonempty candidate set where applicable, compare scanner-reported paths with that set, and preserve the separate synthetic positive control result. The collector does call `leak-scan` on home, evidence, model home and candidate paths; the gap is in verification of coverage.

10. **Medium — G-5 equates empty listeners with stopped processes.** `scenarios/single_factory.py:382-385,874-910` computes `processes_stopped` from cleanup errors and port listeners alone. A harness or service can remain alive after closing its listener, and `testbed down` can return `timeout` or `identity-mismatch` as data without adding a cleanup error. A probe with `processes_stopped:true`, no listeners, and equal broker PIDs returned `G-5: pass` without any PID liveness evidence. **Fix:** retain the started PID/PGID inventory, check each process exited, inspect every `testbed down` and runner stop result, then check the complete port block and broker before/after state.

11. **Low — SF-1 does not independently verify the author model identity and live call record.** `scenarios/single_factory.py:149-166` uses `author.live.provider` and `live_model_available`; `authoring_acceptance` validates the rounds, submission and approval, but neither requires `outcome.model.live == true` and `id == gpt-6-sol` for a live run. A correctly shaped published record from a different model can pass this check. **Fix:** compare the outcome's model kind/provider/id/live fields and its call count with broker stream/session records, while retaining the existing structured validation and digest checks.
