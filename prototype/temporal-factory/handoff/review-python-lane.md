## Findings, ranked

1. **High — Raw provider response escapes through the socket and Python error.** `broker/exo-model.mjs:158-161,201-203,214-216` now places `cause.errorMessage || cause.message` in a `provider` reply. `safeLine` at `:103-108` redacts exact current token strings and JWT-shaped strings, not arbitrary sensitive response fragments. Pi-ai can place the raw SSE response body in that error, as documented in `handoff/pi-ai-credential-audit.md:30-44`. A synthetic loopback HTTP 500 with `backend returned fragment-only-synthetic-secret` produced `RuntimeError: model broker provider: backend returned fragment-only-synthetic-secret` through `PiBrokerModel.stream` (`src/model_broker.py:223-230`). Thus the fragment reaches socket clients and can enter exception capture or evidence. **Reproduced:** yes, with an isolated fixture store and local HTTP server; no real secret. Return fixed kind/status text only.

2. **High — Wall-clock deadline does not bound synchronous broker startup.** `_BudgetedModel.stream` sets `asyncio.timeout` at `src/authoring.py:101-116`, but `PiBrokerModel.stream` immediately calls synchronous `ensure_started` at `src/model_broker.py:182-183`. That method performs blocking socket reads, process launch, and up to 30 seconds of polling (`:42-50,75-111`), so the event loop cannot deliver the timeout during startup. If startup then fails, `BrokerLost` propagates instead of `status: aborted` with `reason: deadline`; if it succeeds, the session can overrun its wall-clock limit. Normal `codex-subscription` selection also starts the broker before the session clock begins (`src/authoring.py:443-445`, `src/admin.py:62-76`). **Reproduced:** yes with an isolated slow/failing `ModelBroker` stub: a 20 ms deadline surfaced `BrokerLost` after 155 ms. No provider contacted.

3. **Medium — Replay silently reorders or drops content.** `PiBrokerModel.to_pi` (`src/model_broker.py:145-179`) gathers all user text before all tool results. For user blocks `[text("before"), toolResult, text("after")]`, it emits `before, after, toolResult`. It also drops user images and assistant reasoning blocks without the private `SIG` envelope. This violates the specified lossless replay and can change a later model request's meaning. **Reproduced:** yes, by direct `to_pi` probes. The standard authoring prompt is text only, which limits ordinary exposure.

4. **Medium — Quota/rate-limit errors can be hidden as budget exhaustion.** `src/model_broker.py:223-230` maps both to `ModelThrottledException`; Strands 1.57 retries that exception, then `_BudgetedModel` (`src/authoring.py:101-109`) raises `model_call_limit` on the next attempt. With `max_model_calls=1`, a provider quota error becomes an `aborted/model_call_limit` outcome rather than an explicit subscription quota failure, contrary to `INTERFACES.md:84`. The wrapper does correctly prevent an additional inner-model request. **Reproduced:** yes with a synthetic throttling model and zeroed retry delay: one call, `aborted/model_call_limit`.

5. **Medium — Losing `ensure_started` process can report a false startup failure.** `src/model_broker.py:101-110` checks the ready file, then raises immediately whenever its own spawned child has exited. In a race, that child may exit 0 after attaching to the winning broker while the winner's `broker-ready.json` is still pending; this caller gets `BrokerLost` instead of retrying the winner's health within its timeout. **Reproduced:** yes with a simulated exited attach child and a health stub that becomes ready on the next check; Python raised after only the first health attempt. The exact timing window was not reproduced with two real Node processes.

6. **Medium — Relative model homes resolve to two different installations.** `ModelBroker.__init__` preserves a relative `home` (`src/model_broker.py:37-40`), then passes it in `EXO_MODEL_HOME` while launching Node with a different `cwd` (`:92-95`). A caller using `EXO_MODEL_HOME=relative-model` resolves the Python socket under its own cwd, while Node resolves the home under `prototype/temporal-factory`; readiness at `:101-105` cannot match. **Reproduced:** path calculation from the repo root showed distinct absolute socket paths; no broker was launched for this probe.

7. **Low — A non-submission tool call can pass after the round cap.** `check_tool_call` at `src/authoring.py:169-183` permits `describe_vocabulary` once a valid draft exists at `max_rounds`, because its `draft_digest` is `None`. The contract says every tool call after the round limit terminates the session, except the implementation's intended revalidation/submission of the accepted draft. **Reproduced:** with `max_rounds=1`, a valid `validate_draft` followed by `describe_vocabulary` ran both tools and returned `no_submission` with no abort.
